● The pipeline is already wired up. Here's the chain:

  1. Xsens driver (xsens_mti_node) publishes raw data to /filter/velocity, /filter/euler,
  /filter/positionlla
  2. xsens_data_conversion subscribes to those, converts units, publishes UGVTelemetry to
  /ngcp/telemetry at 10 Hz
  3. xbee_command_receiver subscribes to /ngcp/telemetry, stores it in _latest_telemetry
  4. When a command comes in, _reply_telemetry uses _latest_telemetry → real data

  You just need to run xsens_data_conversion alongside the Xsens driver. You don't need the
   full telemetry launch (which also starts NTRIP) — just the driver and the converter.

  On the Jetson, run 3 terminals:

  Terminal 1 — Xsens driver (you already have this running):
  ros2 launch xsens_mti_ros2_driver xsens_mti_node.launch.py

  Terminal 2 — Data converter (bridges Xsens → /ngcp/telemetry):
  source install/setup.bash
  ros2 run ugv_telemetry xsens_data_conversion

  Terminal 3 — XBee comms:
  source install/setup.bash
  ros2 launch ugv_comms ugv_comms.launch.py \
    xbee_port:=/dev/ttyUSB0 \
    gcs_mac_address:=0013A200427EA7FC \
    vehicle_mac_address:=0013A20042839F3E 2>&1 | grep -E "\[CMD|\[CTRL"

  On GCS:
  python scripts/gcs_command_simulator.py --xbee-port COM3 --vehicle-mac 0013A20042839F3E

  Now when the simulator sends a Heartbeat, the reply will contain real speed, pitch, yaw,
  roll, altitude, and GPS coordinates from the Xsens — not zeros.
